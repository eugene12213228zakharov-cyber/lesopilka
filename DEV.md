# Лесопилка — разработка

Памятка для продолжения работы с любого компьютера: что это за проект, что сейчас в работе,
как устроен код и что нельзя ломать. Для игроков — [README.md](README.md).

## Коротко

Браузерная arcade idle-игра: игрок таскает брёвна и доски, открывает станки и цеха, нанимает рабочих
и строит деревянный небоскрёб в 20 этажей. Играется на ПК в браузере, без установки.
Движка нет: графика — Three.js (только рисование), вся логика написана в `src/sim.js`.

## Сейчас в работе (обновлено 29.09.2026)

- **Визуал на моделях Kenney — в тесте, в общую не выложено.** Владелец смотрит тест и витрину и
  скажет, какие модели заменить («группа — модель»). Выкладка в общую — только по его слову.
- **Баланс не трогать**, пока владелец не попросит. Отзыв игроков: «всё дорого — прирост от покупки
  слабый по сравнению с ценой». Замер ботом (`node tools/balance.js 14`): покупка стоит 30–40 с дохода
  в первый час и ~2 мин после 4-го часа; живой игрок примерно вдвое медленнее бота
  (через час игры — открыта Делянка, но не Столярка; у бота 24 и 48 мин).
- Общая версия стоит на первом коммите `fdb7d59` (без админки и моделей), тест — на свежем `main`.

Следующий шаг: правки моделей по отзыву → «выкладывай» → `git push origin main`.

## Запуск

- Локально: `node tools/serve.js` → http://localhost:8790 (localhost = тестовый режим: админка F2, своё сохранение).
- `index.html` двойным кликом тоже открывается, но модели Kenney через `file://` не грузятся — будет прежний вид.
- Параметры адреса: `?bot=1` — играет бот, `?speed=8` — ускорение, `?nomodels` — без моделей Kenney
  (сравнить «было/стало»). С `bot`/`speed` игра не сохраняется.
- Нужны: Node.js (любой современный, без npm-зависимостей), git, для заливки — вход в GitHub.

## Выкладка: тест → общая

Сборки нет — что в репозитории, то и на сайте (GitHub Pages из ветки `main`, корень).

```
# один раз на новом компьютере — те же имена удалённых репозиториев, что на рабочем:
git clone https://github.com/eugene12213228zakharov-cyber/lesopilka-test.git lesopilka
cd lesopilka
git remote rename origin test
git remote add origin https://github.com/eugene12213228zakharov-cyber/lesopilka.git
git branch -u test/main

git push              # → тест (main отслеживает test/main)
git push origin main  # → общая версия, только когда владелец сказал «выкладывай»
```

- **Перед каждой выкладкой** поднять номер сборки `window.LESO_BUILD` в `index.html` (например `2026.10.01-1`):
  по нему в ссылки на скрипты и модели добавляется `?v=`, иначе браузер из кеша GitHub (~10 мин)
  смешает старые и новые файлы.
- Сайт пересобирается за ~30–60 с после пуша. Статус: `gh api repos/<владелец>/<репо>/pages --jq .status`.
- Тестовый режим включается сам по адресу (`lesopilka-test` в пути или localhost) — в общей версии админки нет.
- Коммиты — по-русски, от автора, без приписок соавторов и подписей инструментов. В PowerShell 5.1 текст с кириллицей
  передавать файлом в UTF-8 без BOM: `git commit -F файл` (here-string через `-F -` не работает).

## Устройство кода

Классические `<script>` с общими глобальными именами — без сборщика и модулей (кроме импорта three.js
в `index.html` через import map). Имена функций и классов уникальны между файлами.
Порядок загрузки: `util → config → nav → sim → bot → models → assets → kmodels → render → ui → input → audio → admin → main`.

| Файл | Роль |
|---|---|
| `index.html` | страница, HUD, стили, загрузчик, `LESO_BUILD`, `LESO_TEST` |
| `src/config.js` | **все цифры и раскладка карты**: предметы, зоны, кучи и станки (`machine()`), площадки `PADS`, маршруты рабочих `ROUTES`, улучшения, этажи `FLOORS`, `TUNE` |
| `src/sim.js` | класс `Game`: состояние, `step(dt)`, игрок, рабочие, станки, покупатели, машины, корабль, этажи, сохранение, `fastForward` (офлайн) |
| `src/nav.js` | сетка проходимости и поиск пути A* |
| `src/bot.js` | бот-игрок: для прогона баланса и `?bot=1` |
| `src/util.js` | помощники, детерминированный генератор случайных чисел, форматирование |
| `src/models.js` | модели из простых фигур (запасной вид, если Kenney не загрузился) |
| `src/assets.js` | кандидаты Kenney для витрины `KENNEY_GROUPS`, перекраска `RECOLOR`, загрузчик `ModelLib` |
| `src/kmodels.js` | **что где стоит в игре** `MODEL_OF`, запекание моделей, человечки с анимациями, станки, машины, корабль |
| `src/render.js` | класс `View`: сцена по состоянию игры, полёты предметов, подписи, камера, декор |
| `src/ui.js` | деньги, цель, панели «Улучшения / Небоскрёб / Рабочие / Меню», окна, код сохранения |
| `src/input.js` / `audio.js` / `admin.js` | управление (WASD + мышь-джойстик) / звуки синтезом / админка теста |
| `src/main.js` | запуск: модели → сохранение → игровой цикл, автосохранение каждые 10 с, офлайн |
| `showcase.html` + `src/showcase.js` | витрина моделей |
| `tools/` | `serve.js`, `balance.js`, `probe.js`, `savetest.js`, `kenney-copy.js` |

Главное в устройстве:
- **Логика отдельно от графики.** `sim.js` и `bot.js` не знают про Three.js и страницу — их гоняет node.
  Графика только читает состояние; анимации (доска летит в руки) — по событиям из `game.events`.
- **Фиксированный шаг.** `game.step(1/60)` столько раз, сколько набежало реального времени. Бот и офлайн
  крутят тот же `step` без графики — 14 часов игры за ~15 секунд.
- Рабочие ходят по маршрутам `ROUTES` (откуда → куда); выбор задачи — `bestJob` в `sim.js`.

## Правила, которые нельзя ломать

Сохранение игрока — в его браузере (`localStorage`, ключ `lesopilka_save_v1`; в тесте —
`lesopilka_test_save_v1`). Обновление кода его не трогает, но:
- **`SAVE_VERSION` не менять** — сохранение другой версии выбрасывается, игрок начнёт заново.
  Несовместимая правка → писать перенос старого формата в `Game.load()`.
- **id предметов, зон, станков, площадок, улучшений, маршрутов не переименовывать и не удалять** —
  только добавлять новые, иначе купленное пропадёт.
- Цифры баланса менять можно: хранятся уровни и покупки, а не цены.
- Новое поле состояния — с умолчанием в `Game.fresh()`.
- Перед выкладкой — `node tools/savetest.js` (сохранение, загрузка, офлайн) и поднять `LESO_BUILD`.

## Баланс

- `node tools/balance.js 14` — бот проходит игру подряд; `--lunch` — по 40 мин с офлайном между сессиями;
  `--buys` — список всех покупок с ценой в секундах дохода. `node tools/probe.js 7` — состояние цехов на 7-м часу.
- Последний прогон: подряд ~11 ч (Делянка 24 мин, Столярка 48 мин, Магазин ~3 ч, Бумажный цех ~4.5 ч,
  Порт ~7.5 ч); обеденный режим — ~5 ч 20 мин активной игры. Человек — примерно ×2 дольше.
- Рычаги: `FLOOR_BONUS` (×1.1 к ценам за этаж), цены мебели в `ITEMS`, стоимость участков `p_gate_*`,
  требования `FLOORS`, рост цен улучшений (`geo(база, множитель)` в `UPGRADES`), `TUNE.offlineCap` (1 ч).

## Модели (Kenney, лицензия CC0)

- Кандидаты лежат в `assets/kenney/<набор>/<модель>.glb` (112 шт.), список — `KENNEY_GROUPS` в `src/assets.js`.
  В игре используется то, что указано в `MODEL_OF` (`src/kmodels.js`).
- **Поменять модель в игре** = поменять ключ в `MODEL_OF`. Если модели нет среди кандидатов — добавить её
  в `KENNEY_GROUPS` и выполнить `node tools/kenney-copy.js` (копирует из `_raw/kenney`).
- Наборы целиком в git не лежат (`_raw/` в `.gitignore`). На новом компьютере скачать нужные архивы
  с kenney.nl и распаковать в `_raw/kenney/<набор>/`: mini-characters, factory-kit, furniture-kit,
  nature-kit, car-kit, watercraft-kit, city-kit-industrial, city-kit-commercial.
- Статичные модели **запекаются** (`bakeModel`) в одну геометрию с цветом в вершинах: цвет берётся из материала
  или из пикселя палитры `Textures/colormap.png` по UV. Поэтому всё рисуется одним материалом и годится
  для `InstancedMesh`. `fittedGeo` вписывает модель в нужный размер, дном на землю.
- У старых наборов (природа, мебель) очень светлая палитра — перекраска по имени материала в `RECOLOR`.
- Человечки — живые (кости + `AnimationMixer`): «стоит / идёт / бежит»; «несу стопку» = ноги из ходьбы +
  руки из `holding-both` (клипы разрезаны по костям `arm-left` / `arm-right`). Каски — полусфера на кости `head`.
- Модели не загрузились (нет сети, `file://`) или `?nomodels` → всё рисуется моделями из `models.js`.
- Без моделей Kenney остались: доски, брус, щиты, ножки, мешки опилок, картон, стеллажи, прилавок, краны, небоскрёб.

## Грабли (уже наступали)

- Путь рабочих строится с запасом 0.55 м от станков — меньше радиуса игрока (0.45) бот цеплялся за углы.
- Грузчик выбирает, куда везти, по заполненности **по каждому предмету** и с приоритетом «голодного» станка
  (всё для сборки есть, кроме этого предмета) — иначе верстак или прессы простаивают.
- Маршруты на продажу берут только излишки (`excess`), иначе мебели не достаётся упаковке.
- «Стройка в приоритете» (`s.sitePriority`): рабочие продаж не трогают то, что нужно этажу, если есть строители.
- Мусорка забирает вещи, только если игрок стоит — иначе выкидывал всё на бегу.
- Каска: её размер задаётся в единицах кости головы (кость наследует масштаб человечка), иначе вырастает вдвое.
- Встроенные браузеры-превью (в редакторах) почти останавливают `requestAnimationFrame`, когда окно не на экране —
  для проверки крутить `__game.step()` и `__view.frame()` из консоли. Отладка в консоли: `__game`, `__view`, `__input`, `__admin`.
