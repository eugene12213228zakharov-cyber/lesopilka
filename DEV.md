# Лесопилка — разработка

Памятка для продолжения работы с любого компьютера: что это за проект, что сейчас в работе,
как устроен код и что нельзя ломать. Для игроков — [README.md](README.md).

## Коротко

Браузерная arcade idle-игра: игрок таскает брёвна и доски, открывает станки и цеха, нанимает рабочих
и строит деревянный небоскрёб в 20 этажей. Играется на ПК в браузере, без установки.
Движка нет: графика — Three.js (только рисование), вся логика написана в `src/sim.js`.

## Сейчас в работе (обновлено 30.09.2026)

- **Направление сменилось:** это уже не игра «почилить в обед», а заготовка под коммерческий выпуск (площадку
  и монетизацию владелец пока не выбирает — сначала доводим то, что есть). Длину игры в 5–10 ч больше не держим:
  в коммерческую игру должны возвращаться, а не пройти и забыть. Обеденный режим бота (`--lunch`) — не цель.
- **Баланс экономики теперь за разработчиком** (владелец предлагает идеи). Решения — с замером ботом, цифры — сюда.
- **Правки по отзывам игроков — выложены в обе версии 30.09 (`e9d1b8c`).** Отзывы — из Google-формы (8 шт. на 30.09).
  Сделано: карточка корабля на экране; опилки со всех станков столярки; улучшение «Склады у станков: больше»;
  второй прилавок; вторая линия упаковки (в бумажном цехе); конвейер в порт; рабочие — номера, цвет каски
  по цеху, список по цехам, подсветка и «📍 показать»; над стоящим рабочим — чего он ждёт; минимальная партия
  у рабочих; бег налегке; на площадках — что даст покупка. Подробности — «Рабочие: выбор работы и чего ждут» ниже.
- **Живые игроки быстрее бота в поздней игре:** один из первых игроков прошёл все 20 этажей и улучшения рабочих
  за ~7 ч в игре (16-й этаж — на 6-м часу), бот — за ~11 ч подряд. Оценка «человек вдвое медленнее» верна
  только для первого часа.
- **Продажа досок упиралась в 3 места у прилавка**, а не в вместимость: у бота места заняты 2.7–2.9 из 3,
  ещё 1–1.5 человека ждут; продажи 63–78 досок/мин с 45-й минуты до 6-го часа, хотя «Покупатели досок: чаще»
  растёт с 4-го уровня до 8-го. Отзыв «расширять склады досок» был про прилавок («несёт, а там 38 из 40»).
  Решение владельца — **второй прилавок** (`p_counter2`, $4000 после первого продавца досок): свои 3 места,
  своя касса, и **каждый прилавок приводит своих покупателей** (поток делится на число прилавков, лимит
  `c1Max` — на прилавок). Замер: продажи 174–186 досок/мин (×2.4), прилавки полны на 65–73% вместо 79–85%,
  бот проходит игру за ~9 ч вместо ~11. Вариант «общий поток» давал +26…62% и не разгружал прилавки.
  Верхние уровни «Покупатели досок» теперь не впустую: после 4-го покупатель берёт больше досок за раз (до 3 + уровень − 4,
  `c1Take`) — на 3-м часу 258 досок/мин вместо 186.
- На заметку: в поздней игре бота держат щиты — строители и грузчик щитов ждут их (прессов два).
- Открытый вопрос: код сохранения легко раскодировать и подделать (это base64 от JSON). Без сервера защиты нет —
  варианты владельцу предложены (подпись + проверка правдоподобия сейчас; вход и облачные сохранения — позже).
- **Выкладка с 30.09 — сразу в обе версии** (слово владельца: «заливай сразу в обе версии»); проверки перед заливкой
  те же: `savetest`, `compat.js` против общей, бот.
- **Общая версия = тест = свежий `main`.** 30.09 вечером (`e9d1b8c`) — правки по отзывам, второй прилавок, аллея,
  вторая упаковка, конвейер, новое начало с делянки; сохранения у всех сброшены (решение владельца). 30.09 ночью —

   посади на пне → вальщик → стройка. **Сохранения сброшены всем:** `SAVE_VERSION` 2; вернувшемуся — окно
   «🌲 Большое обновление» (`UI.showReset`). «Делянка» — лесной термин; переименовать («Лес» / «Лесной участок») —
   решает владелец.
3. **Чтобы играли долго — небоскрёб оживает** (раскладка владельца 30.09: после порта «ничего не происходит»,
   пустые этажи, игрок часто стоит без дела):

   - **15-й этаж — новая зона «Верфь»** (у моря южнее порта, лодки из бруса и щитов) — после казино;

## Запуск

- Локально: `node tools/serve.js` → http://localhost:8790 (localhost = тестовый режим: админка F2, своё сохранение).
- `index.html` двойным кликом тоже открывается, но модели Kenney через `file://` не грузятся — будет прежний вид.
- Параметры адреса: `?bot=1` — играет бот, `?speed=8` — ускорение, `?nomodels` — без своих моделей и Kenney,
  прежние фигуры из `models.js` (свет и материалы остаются новые). С `bot`/`speed` игра не сохраняется.
- Нужны: Node.js (любой современный, без npm-зависимостей), git, для заливки — вход в GitHub.

## Выкладка: тест → общая

Сборки нет — что в репозитории, то и на сайте (GitHub Pages из ветки `main`, корень).

```
# один раз на новом компьютере — те же имена удалённых репозиториев, что на рабочем:
git clone https://github.com/eugene12213228zakharov-cyber/lesopilka-test.git lesopilka
cd lesopilka
git remote rename origin test
git remote add origin https://github.com/eugene12213228zakharov-cyber/lesopilka.git
git branch -u test/main

git push              # → тест (main отслеживает test/main)
git push origin main  # → общая версия (с 30.09 владелец: правки заливать сразу в обе версии)
```

- **Перед каждой выкладкой** поднять номер сборки `window.LESO_BUILD` в `index.html` (например `2026.10.01-1`):
  по нему в ссылки на скрипты и модели добавляется `?v=`, иначе браузер из кеша GitHub (~10 мин)
  смешает старые и новые файлы.
- Сайт пересобирается за ~30–60 с после пуша. Статус: `gh api repos/<владелец>/<репо>/pages --jq .status`.
- Тестовый режим включается сам по адресу (`lesopilka-test` в пути или localhost) — в общей версии админки нет.
- Коммиты — по-русски, от автора, без приписок соавторов и подписей инструментов. В PowerShell 5.1 текст с кириллицей
  передавать файлом в UTF-8 без BOM: `git commit -F файл` (here-string через `-F -` не работает).

## Устройство кода

Классические `<script>` с общими глобальными именами — без сборщика и модулей (кроме импорта three.js
в `index.html` через import map). Имена функций и классов уникальны между файлами.
Порядок загрузки: `util → config → nav → sim → bot → models → look → craft → assets → kmodels → render → ui → input → audio → admin → main`.

| Файл | Роль |
|---|---|
| `index.html` | страница, HUD, стили, загрузчик, `LESO_BUILD`, `LESO_TEST` |
| `src/config.js` | **все цифры и раскладка карты**: предметы, зоны, кучи и станки (`machine()`), площадки `PADS`, маршруты рабочих `ROUTES`, улучшения, этажи `FLOORS`, `TUNE` |
| `src/sim.js` | класс `Game`: состояние, `step(dt)`, игрок, рабочие, станки, покупатели, машины, корабль, этажи, сохранение, `fastForward` (офлайн) |
| `src/nav.js` | сетка проходимости и поиск пути A* |
| `src/bot.js` | бот-игрок: для прогона баланса и `?bot=1` |
| `src/util.js` | помощники, детерминированный генератор случайных чисел, форматирование |
| `src/models.js` | модели из простых фигур (запасной вид для `?nomodels` и если Kenney не загрузился) |
| `src/look.js` | **как выглядит мир**: материал с поверхностями `SURF` (дерево, металл, бетон…), свет `LOOK`, отражения неба, покрытия земли |
| `src/craft.js` | **свои модели**: детали с фасками `Kit`, пиломатериалы, станки, постройки, небоскрёб, краны, лесовоз; `OWN_GROUPS` для витрины |
| `src/assets.js` | кандидаты Kenney для витрины `KENNEY_GROUPS`, перекраска `RECOLOR`, загрузчик `ModelLib` |
| `src/kmodels.js` | **что где стоит в игре** `MODEL_OF`, запекание моделей Kenney, человечки с анимациями |
| `src/render.js` | класс `View`: сцена по состоянию игры, полёты предметов, подписи, камера, декор |
| `src/ui.js` | деньги, цель, панели «Улучшения / Небоскрёб / Рабочие / Меню», окна, код сохранения |
| `src/input.js` / `audio.js` / `admin.js` | управление (WASD + мышь-джойстик) / звуки синтезом / админка теста |
| `src/main.js` | запуск: модели → сохранение → игровой цикл, автосохранение каждые 10 с, офлайн |
| `showcase.html` + `src/showcase.js` | витрина моделей |
| `tools/` | `serve.js`, `balance.js`, `probe.js`, `savetest.js`, `compat.js`, `kenney-copy.js`, `formfields.js` |

Главное в устройстве:
- **Логика отдельно от графики.** `sim.js` и `bot.js` не знают про Three.js и страницу — их гоняет node.
  Графика только читает состояние; анимации (доска летит в руки) — по событиям из `game.events`.
- **Фиксированный шаг.** `game.step(1/60)` столько раз, сколько набежало реального времени. Бот и офлайн
  крутят тот же `step` без графики — 14 часов игры за ~15 секунд.
- Рабочие ходят по маршрутам `ROUTES` (откуда → куда); выбор задачи — `bestJob` в `sim.js`.

## Дороги, машины и люди

- Раскладка — `ROAD`, `CROSSINGS`, `LIGHTS`, `LIGHT` в `config.js`. Главная дорога вдоль X уходит на западе в тоннель,
  у моря поворачивает на север (береговая) в северный тоннель. Движение правостороннее. Холм северного тоннеля —
  стена для игрока (`rebuild`). **Южной дороги нет с 30.09:** машины по ней не ездили, рабочие только ходили в обход
  до «зебр» — на её месте аллея, по ней приходят покупатели (`ROAD.southZ` — докуда она тянется на юг).
- **Машины** едут по маршрутам `TRUCK_PATHS` (`sim.js`: ломаная с дугами на поворотах, у дуги своя скорость):
  лесовоз — из западного тоннеля к складу и дальше налево в северный, оптовик — из северного направо к оптовому
  складу и в западный. Появляются там же, где раньше, — поэтому подвоз брёвен и загрузка оптовика по времени
  прежние. Тормозят у склада, на красный у стоп-линии, за другой машиной и перед людьми на проезжей части.
- **Светофор** в центре — с датчиком: пешеходам зелёный, пока к стоп-линии не подъедет машина (`lightStep`).
  Состояние не сохраняется. На маршрутах светофор стоит только там, где машины уже уезжают (`out`), — на экономику
  не влияет. Остальные переходы — «зебры»: пешеход пропускает подъезжающую машину (`carComing`), машина — пешехода.
- **Люди по правилам.** Для рабочих и бота проезжая часть непроходима, кроме переходов (`ROAD_BLOCKS` в сетке `nav`),
  на светофоре ждут зелёный (`crossWait`). У каждого рабочего своя лихость `w.rash` (8–29%): с этой вероятностью,
  если путь идёт через дорогу, он спешит (`w.hurry`) — идёт напрямик по сетке `navFree` и не ждёт. Таких машины
  не ждут: сбитый отлетает, лежит 1.6 с (`knock`), груз разлетается россыпью (`loose`) — подбирает только игрок.
- **Игрок** ходит где хочет. Стоящая машина — стена (`hits`), едущая сигналит и сбивает: 0.9 с лежит, всё из рук
  разлетается на 1–3.6 м; подбирается, проходя рядом (медленнее, чем с кучи), через 60 с пропадает (`TUNE.looseLife`).
  Бот (`g.soft`) — осторожный игрок: ходит по переходам, машины его пропускают.
- **Покупатели досок** — места продажи `STALLS` в `config.js`: у леса (прилавок у леса, идут с востока вдоль главной
  дороги) и на лесопилке (два прилавка, идут с юга по аллее); у каждого своя очередь (`this.stalls`), места, касса;
  каждый прилавок приводит своих покупателей. Покупатели магазина — по аллее с юга.
- **Покупатели** приходят по аллее с юга и уходят по ней (`far` / `gone`). Появляются сразу за краем
  того, что видит игрок (`seen`, `farZ`); игрок далеко или перемотка — прямо у входа, как раньше. Лимиты
  `c1Max` / `c4Max` считают только тех, кто уже вошёл.
- Счётчики `stats.hitMe` / `stats.hitW` — в Меню → Статистика.

## Рабочие: выбор работы и чего ждут

- **Выбор работы** — `bestJob` в `sim.js`: заполненность по каждому предмету, «голодный» станок, только излишки
  (`excess`), «Стройка в приоритете». **Партия:** рабочий не идёт, если донесёт меньше половины своих рук или склада
  (`TUNE.minBatch`), а там, куда несёт, уже заполнено на 75% (`TUNE.batchFill`) — иначе ходил бы «с двумя досками
  к складу 38 из 40». Голодному станку и полупустому складу везёт сколько есть. Строже (без `batchFill`) — бот
  проходил игру на ~15 мин дольше: станки пустели, пока рабочий ждал места.
- **Продавцы досок носят сразу** (без «только излишки»: у леса продавец ждал 20 досок и стоял). На лесопилке
  продавец уступает доски столярке (`yield` в `ROUTES.boards`, `routeExcess`) — берёт только излишки, пока у пресса
  меньше половины досок и грузчик досок столярки работает; досок у пилорам больше половины — носит в любом случае
  (иначе выходы пилорам стояли 80/80, а прилавки пустые, и порт открывался на час позже).
- **Посадка понятнее:** на пнях полупрозрачный саженец, над ближайшим к игроку — «🌱 Встань — посадишь дерево»;
  после первой рубки — подсказка (`s.tips.fell`), лес кончается без лесника — цель «посади деревья».
- **Телефон** (узкий экран): подписи мельче, над рабочим — короткая причина (`workerWhy` → `short`), «что даст» —
  только у площадки рядом (`near`); баннер цели — над кнопками.
- **Чего ждёт** — `workerWhy(w)`: одна функция и для подписи над головой, и для списка рабочих. Считает по текущему
  состоянию тем же `bestJob` (с объектом `why`), поэтому зовётся только из графики и только для стоящих: `w.still` —
  сколько стоит без дела, подпись — после `TUNE.idleShow` (2.5 с). Переход: `w.xwait` — `'light'` / `'car'`
  (`crossWait` теперь говорит, чего ждёт). `workerDoing(w)` — что делает сейчас, для строки в списке.
- **Кто есть кто:** номер = порядок найма (сквозной, над головой — пока открыт список). Цех — `workerZone(pad)`:
  куда носит (если носит и в зону, где нанят, — она); по нему цвет каски (`helmet` в `ZONES`, строители белые)
  и группа в списке. «📍» — `View.focusOn`: камера на 6 с у рабочего, пока игрок не пошёл; подробно рисуется всё
  вокруг камеры (`View.cx/cz`), а не вокруг игрока.
- **Опилки** дают все станки столярки: брусовальные, прессы, токарные и верстаки — чем больше мебели, тем больше
  опилок на коробки для неё. Пневмопровод раскладывает их по бункерам `DUST_BUNKERS`, куда свободнее. Вторая линия упаковки — в бумажном цехе
  (`cardM2`, `boxM2`, `packer2`, средний и южный ряды): без второй картонной машины она бессмысленна — картонная (3 с
  на лист) медленнее коробочного и упаковки.
- **Конвейер в порт** (`p_belt`, `BELT` в `config.js`, `beltStep` / `beltRide` в `sim.js`, `buildBelt` / `syncBelt` в
  `render.js`): с погрузки `belt_in` у упаковок коробки по одной встают на ленту (`BELT.loadT`), едут со скоростью
  `u_belt` не ближе `BELT.gap` и в конце ложатся на склад порта; склад полон — лента встаёт. Путь владельца — по
  южному краю карты, вверх по просвету между магазином и портом, ~133 м. Лента не стена; игрок на ленте едет с ней
  (`beltRide` в `movePlayer`), на погрузке и у склада — нет. Что едет — `s.belt` ({ it, d }), сохраняется.
  Улучшение «Конвейер: быстрее» видно только после покупки ленты (`pad` в `UPGRADES`, `Game.upgOpen`).

## Небоскрёб: жильцы и облёт

- **Жильцы** — `TENANT_FLOORS` и `TENANTS` в `config.js`: на этаж без новой зоны въезжает жилец, игрок выбирает одного
  из двух, бонусы складываются (`Game.teff`, пересчёт — `tenantCalc` при въезде и загрузке). Предлагаются только те,
  чей бонус уже на что-то действует (`avail`; отзыв владельца: «баф на корабль до порта — как игрок поймёт?»):
  корабль — после причала, мебель — со столярки, рабочие — когда кто-то нанят, страховка — когда открыта лесопилка.
  Страховая — одна на игру (`once`). Предложение — `tenantOffer` (случайно, `this.rnd()`) → `s.tenantPending` → выбор
  `pickTenant`. Не выбрал — ждёт в «Небоскрёбе», чип этажа горит «🏠 выбери жильца»; окно выбора открывается после
  облёта (`UI.tenantAt`). Сохранения до жильцов: на уже построенные этажи выбрать предлагают при загрузке (`Game.load`).
- Где действуют бонусы: `wSpeed()` и `capOf` (рабочие), таймеры покупателей (прилавки и магазин), `stationStep`
  (станки), `cap()` выходов станков, `price()` (цены, мебель), `growT()` (лес), `plSpeed` (игрок), `sh.left` (корабль),
  `knock` (страховка). Сила — на треть меньше первой версии: жильцы вместе с починкой улучшений рабочих порта сжимали
  игру на 2 ч. Бот выбирает жильцов по списку предпочтений в `bot.js`.
- **Облёт** — `View.towerShot` в `render.js`: игровая камера смотрит вниз с ~22 м, выше неё небоскрёб и кран не видны
  никогда (отзыв владельца). Этаж достроен или кнопка «🔭 Посмотреть на небоскрёб» → камера на 3–4 с отъезжает так,
  чтобы небоскрёб и кран вошли целиком: расстояние — по углу обзора камеры, по высоте и по ширине (на телефоне стоймя
  тоже), туман отъезжает вместе с камерой (`fog0`), подписи прячутся, подробно рисуется всё вокруг небоскрёба.
- **Починено:** «Электрокары» (`u_wSpeed2`) и «Тележки» (`u_wCap2`) порта покупались, но не действовали — теперь
  учтены в `wSpeed()` и `capOf`.

## Правила, которые нельзя ломать

Сохранение игрока — в его браузере (`localStorage`, ключ `lesopilka_save_v1`; в тесте —
`lesopilka_test_save_v1`). Обновление кода его не трогает, но:
- **`SAVE_VERSION` не менять** (сейчас 2) — сохранение другой версии выбрасывается, игрок начнёт заново. Поднимали
  один раз, осознанно: 30.09 — новое начало с делянки, сброс всем по решению владельца.
  Несовместимая правка → писать перенос старого формата в `Game.load()`.
- **id предметов, зон, станков, площадок, улучшений, маршрутов не переименовывать и не удалять** —
  только добавлять новые, иначе купленное пропадёт.
- Цифры баланса менять можно: хранятся уровни и покупки, а не цены.
- Новое поле состояния — с умолчанием в `Game.fresh()`.
- Перед выкладкой — `node tools/savetest.js` (сохранение, загрузка, офлайн) и поднять `LESO_BUILD`.
- Перед выкладкой в общую — `node tools/compat.js <коммит общей версии> 3`: бот 3 часа играет на той версии,
  что сейчас у игроков, и проверяет, что новая открывает это сохранение без потерь и играет дальше.
  Коммит общей: `git rev-parse --short origin/main`.

## Модели: свои и Kenney

- Что где стоит в игре — `MODEL_OF` (`src/kmodels.js`). **Поменять модель в игре** = поменять ключ в `MODEL_OF`.
  Ключ `own/…` — своя модель из `src/craft.js`, `набор/модель` — Kenney. Станки: `'kenney'` в `MODEL_OF.st`
  возвращает прежнюю сборку из деталей Factory Kit (`KENNEY_ST`), `MODEL_OF.tower` — этажи, леса и крыша.
- Витрина (`showcase.html`) показывает сверху свои модели, ниже кандидатов Kenney; **★ ставится сама по `MODEL_OF`**.

### Свои модели (`src/craft.js`)

- Модель собирается из деталей в `Kit`: `box` (коробка с фасками), `cyl` (цилиндр/конус), `lathe` (тело вращения
  по профилю), `prism` (вытянутый многоугольник), `tube`/`pipe` (трубы). Всё в метрах; предметы — длинной стороной
  вдоль X, дном на y=0; станки — вход слева (−X), выход справа (+X), в габарите 3.2 × 2.4.
- В вершинах лежат цвет, поверхность `surf` (`SURF` в `look.js`) и центр годовых колец `ring`. Шейдер по поверхности
  рисует волокна дерева (на торцах — кольца), неровную краску, шлифовку стали, поры бетона, гофру картона и задаёт
  шершавость/металличность. Дерево само выбирает направление волокон по повороту детали.
- `geo({ ao: [высота, множитель] })` затемняет низ модели — будто от пола. Станки, постройки и машины возвращают
  `{ g, anim(t, работает) }`, как прежние из `models.js`; верстак получает id станка и показывает, что на нём собирают.
- Проверять удобно в витрине — там станки работают (`anim(t, true)`).

### Модели Kenney (лицензия CC0)

- Кандидаты лежат в `assets/kenney/<набор>/<модель>.glb` (112 шт.), список — `KENNEY_GROUPS` в `src/assets.js`.
  Если модели нет среди кандидатов — добавить её в `KENNEY_GROUPS` и выполнить `node tools/kenney-copy.js`
  (копирует из `_raw/kenney`).
- Наборы целиком в git не лежат (`_raw/` в `.gitignore`). На новом компьютере скачать нужные архивы
  с kenney.nl и распаковать в `_raw/kenney/<набор>/`: mini-characters, factory-kit, furniture-kit,
  nature-kit, car-kit, watercraft-kit, city-kit-industrial, city-kit-commercial.
- Статичные модели **запекаются** (`bakeModel`) в одну геометрию с цветом в вершинах: цвет берётся из материала
  или из пикселя палитры `Textures/colormap.png` по UV. Поэтому всё рисуется одним материалом и годится
  для `InstancedMesh`. `fittedGeo` вписывает модель в нужный размер, дном на землю.
- У старых наборов (природа, мебель) очень светлая палитра — перекраска по имени материала в `RECOLOR`.
- Человечки — живые (кости + `AnimationMixer`): «стоит / идёт / бежит»; «несу стопку» = ноги из ходьбы +
  руки из `holding-both` (клипы разрезаны по костям `arm-left` / `arm-right`). Каски — полусфера на кости `head`.
- Модели Kenney не загрузились (нет сети, `file://`) → на их местах модели из `models.js`, свои остаются.
  `?nomodels` → всё из `models.js`.

### Свет и материалы (`src/look.js`)

- Тонмаппинг AgX (`LOOK.tone`; ACES ярче и насыщеннее — ближе к «игрушечному»), солнце `LOOK.sunI` с тенью,
  рассеянный свет и отражения — от неба-градиента через PMREM (`LOOK.envI`), без HemisphereLight.
- Всё, что рисуется `MAT.flat`/`MAT.vc`, — `MeshStandardMaterial` с поверхностями; человечки и прочее с текстурой —
  `plainMaterial`. Lambert не использовать: он не видит отражения неба и в тени станет чёрным.
- Покрытия земли — текстуры, нарисованные на canvas при запуске (`groundTexture`): трава, земля с опилками, лесная
  почва, бетон цеха, плитка, плиты порта, гравий, асфальт.

## Грабли (уже наступали)

- Путь рабочих строится с запасом 0.55 м от станков — меньше радиуса игрока (0.45) бот цеплялся за углы.
- Грузчик выбирает, куда везти, по заполненности **по каждому предмету** и с приоритетом «голодного» станка
  (всё для сборки есть, кроме этого предмета) — иначе верстак или прессы простаивают.
- Маршруты на продажу берут только излишки (`excess`), иначе мебели не достаётся упаковке.
- «Стройка в приоритете» (`s.sitePriority`): рабочие продаж не трогают то, что нужно этажу, если есть строители.
- Мусорка забирает вещи, только если игрок стоит — иначе выкидывал всё на бегу.
- Каска: её размер задаётся в единицах кости головы (кость наследует масштаб человечка), иначе вырастает вдвое.
- Свои модели не прогонять через `fittedGeo`: он масштабирует вершины, а центр годовых колец (`ring`) остаётся
  старым. Склеивать геометрии — `concatGeos` (переносит `surf`/`ring`), не `mergeParts`.
- Встроенные браузеры-превью (в редакторах) почти останавливают `requestAnimationFrame`, когда окно не на экране —
  для проверки крутить `__game.step()` и `__view.frame()` из консоли. Отладка в консоли: `__game`, `__view`, `__input`, `__admin`.

## Идеи на потом

- Свои человечки со взрослыми пропорциями (рабочие в спецовке и жилете) вместо mini-characters; свой сухогруз.
- Обжитость цехов: поддоны, бочки, огнетушители, колонны и фермы по краю зоны; пневмопровод трубами между цехами.
- Куча опилок у пилорамы (выход `dust`) — растущим конусом, а не столбиками мешков.
- Больше «сочности»: искры и опилки у пилы, конфетти на новый этаж, звук пилы.
- Интерфейс построже: шрифт, плашки подписей над площадками.
